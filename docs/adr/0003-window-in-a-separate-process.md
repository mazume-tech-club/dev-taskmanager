# ウィンドウは常駐プロセスとは別プロセスで動かす

常駐プロセス（トレイ、サンプラー、ログ）は Process Commit 約 10 MB で済むが、egui のウィンドウは GPU コンテキストを
持つだけで 40 MB 以上を確保し、ウィンドウを隠しても解放されない（eframe 0.37 の既定レンダラー wgpu では
NVIDIA ドライバで 330 MB、glow に切り替えても 50 MB 前後）。winit はプロセス内でイベントループを一度しか作れないので、
表示のたびにウィンドウを作り直す方式も取れない。

採用: `commitwatch.exe` は引数なしで常駐プロセスになり、ウィンドウは `--window` 引数で起動した別プロセスが担当する。
常駐側は直近 600 秒の Sample と Top Processes を名前付き共有メモリ（`Local\CommitWatch.state`、seqlock）に毎秒書き、
ウィンドウ側はそれを読むだけにする。ウィンドウを閉じるとそのプロセスは終了し、常駐側のメモリは増えない。

## Considered Options

- **1 プロセスでウィンドウを隠す**: 隠しても GPU コンテキスト分のメモリが残る。却下。
- **ソフトウェア描画**: egui に実用的なソフトウェアバックエンドが無い。却下。
- **別プロセス + 共有メモリ**: 常駐 10 MB、表示中のみ +45 MB。採用。

## Consequences

- 設定変更はウィンドウ側が `config.toml` に書き、常駐側が 5 秒ごとの更新時刻チェックで読み直す。
- 常駐側が落ちてもウィンドウは「接続中」表示で待ち、ウィンドウが落ちても監視とログは続く。
- 2 回目の起動（exe をもう一度ダブルクリック）は既存ウィンドウを前面に出すだけで、プロセスは増えない。
- レンダラーは glow（OpenGL）に固定し、eframe の `system_fonts` 機能も外す。日本語は OFL ライセンスの
  BIZ UDGothic を JIS 第 1 水準までに絞って同梱する（1.4 MB）。システムフォント（Meiryo）を読むと 60 MB 増えた。
